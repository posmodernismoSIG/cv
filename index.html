ArcGIS Enterprise Integration

My backend systems treat ArcGIS Enterprise as an active geospatial engine — not just a map viewer. It executes analysis, manages spatial layers, runs geoprocessing services, and stores raster datasets — all orchestrated through Python backends.

I design Python middleware APIs (Django DRF, FastAPI, Flask) that sit between client apps and ArcGIS Enterprise, handling authentication, request routing, spatial validation, and response normalization so frontends stay ESRI-agnostic and portable.

Python is the integration language throughout: arcpy for deep ArcGIS Pro automation and geoprocessing services, arcgis SDK for REST-based access to portals and feature layers, and Pydantic for enforcing strict spatial input contracts. All async workers run on AWS EKS / Kubernetes, keeping synchronous endpoints fast.

⬡ Server Integration ArcGIS Server · Portal

Integrating ArcGIS Enterprise with Python backends starts with connecting to Portal for ArcGIS and ArcGIS Server through its REST API surface. I use token-based authentication (built-in or IWA), manage service registration, and orchestrate publishing of map services, feature services, and geoprocessing services programmatically — eliminating manual ArcGIS Manager steps from CI/CD pipelines.

python arcgis SDK · portal auth
# Connect to ArcGIS Enterprise portal
from arcgis.gis import GIS

gis = GIS(
    url="https://arcgis.myorg.co/portal",
    username=settings.ARCGIS_USER,
    password=settings.ARCGIS_PASS,
    verify_cert=True
)
# Search and access a published feature service
item = gis.content.search(
    "title:deforestation_2024 AND type:Feature Service",
    max_items=1
)[0]
flayer = item.layers[0]  # FeatureLayer object
⬡ Server-Side Library Setup Python · Conda · ArcPy

ArcGIS Enterprise ships with its own Python environment managed by Conda. I configure server-side environments by cloning the default arcgispro-py3 environment, installing geospatial dependencies into it, and registering the environment with ArcGIS Server so geoprocessing scripts execute with full library access — including arcpy, GDAL, Rasterio, FastAPI, and custom packages from internal registries.

bash conda env · arcgis server registration
# Clone default env and install geospatial deps
conda create --name geoenv --clone arcgispro-py3
conda activate geoenv

pip install rasterio gdal shapely geopandas
pip install arcgis==2.3.0 pydantic fastapi celery

# Register env with ArcGIS Server (Windows Server)
cd C:\ArcGIS\Server\tools\PythonEnvManagement
python RegisterPythonEnv.py \
  --env C:\conda\envs\geoenv \
  --serverUrl https://arcgis-server.myorg.co \
  --username siteadmin
⬡ ArcGIS Data Store Relational · Raster · Cloud S3

ArcGIS Data Store provides three registered store types used in production. The Relational Data Store (PostgreSQL-based) backs hosted feature layers. The Raster Data Store caches imagery tiles for image services, efficiently serving multi-band satellite rasters to web clients. The Cloud Data Store (backed by AWS S3) holds large-volume raster collections from Prisma and ABACO pipelines without saturating server disk. I manage store registration, backup strategy, and failover on live deployments.

python register cloud data store via SDK
from arcgis.gis import GIS

gis = GIS("https://portal.myorg.co", "admin", pwd)

# Register an S3 bucket as a cloud data store
ds_config = {
    "type": "cloudStore",
    "info": {
        "objectStore": "s3://procalculo-imagery",
        "provider": "amazon",
        "region": "us-east-1",
        "credentialType": "IAMRole"
    }
}
gis.datastores.add(ds_config, name="S3ImageryStore")
⬡ Push Data via REST API applyEdits · GeoJSON · Feature Service

I push spatial analysis results and processed satellite detections directly into ArcGIS Enterprise hosted feature layers using the applyEdits REST endpoint. This keeps ABACO deforestation polygons and Prisma detection footprints live and queryable inside the Portal without manual imports. The Django backend batches edits, handles geometry serialization to ESRI JSON, and manages token refresh between long-running batch operations.

python applyEdits · REST endpoint · batch push
import requests, json

# Get token from ArcGIS Enterprise
token_url = "https://arcgis.myorg.co/portal/sharing/rest/generateToken"
token = requests.post(token_url, data={
    "username": user, "password": pwd,
    "client": "referer", "f": "json"
}).json()["token"]

# Push deforestation polygon to Feature Service
edits_url = (
    "https://arcgis.myorg.co/server/rest/services/"
    "ABACO/FeatureServer/0/applyEdits"
)
payload = {
    "adds": json.dumps([{
        "geometry": {
            "rings": polygon_rings,
            "spatialReference": {"wkid": 4326}
        },
        "attributes": {
            "area_ha": area, "date_detected": date_ts,
            "confidence": score, "source": "ABACO-v3"
        }
    }]),
    "token": token, "f": "json"
}
result = requests.post(edits_url, data=payload).json()
⬡ arcgis SDK for Python FeatureLayer · SeDF · Portal

The arcgis Python SDK provides a high-level object model over the ArcGIS REST API. I use it for querying feature layers into Spatially Enabled DataFrames (GeoPandas-compatible), publishing analysis results as new hosted layers, invoking geoprocessing services asynchronously, and managing portal content programmatically. It integrates cleanly into Django management commands and Celery tasks for scheduled data synchronization pipelines.

python arcgis SDK · FeatureLayer · SeDF · publish
from arcgis.gis import GIS
from arcgis.features import FeatureLayer
from arcgis.geometry import filters

gis = GIS("https://portal.myorg.co", token=token)
layer = FeatureLayer("https://...server/rest/.../0", gis=gis)

# Query into Spatially Enabled DataFrame
sdf = layer.query(
    where="area_ha > 10 AND confidence >= 0.85",
    geometry_filter=filters.intersects(aoi_geom),
    return_geometry=True,
    as_df=True
)

# Run pipeline, publish result back as hosted layer
result_sdf = run_analysis_pipeline(sdf)
result_sdf.spatial.to_featurelayer(
    title="ABACO_Results_2024",
    gis=gis,
    folder="analysis_outputs"
)
⬡ ArcPy Server Automation Geoprocessing · Raster · Change Detection

For operations requiring deep ArcGIS Pro capabilities — multi-temporal change detection, model publishing, toolbox execution — I use arcpy in server-side scripts registered as ArcGIS Geoprocessing Services. These run on the ArcGIS Server environment, consume imagery from the Data Store, and write output feature classes and raster datasets back to registered geodatabases. The Django backend triggers them via GP service REST calls with async job polling.

python arcpy · NDVI change detection · GP service
import arcpy

# Server-side GP script: NDVI change detection
arcpy.env.workspace = r"\\datastore\imagery\abaco"
arcpy.env.overwriteOutput = True

before = arcpy.Raster("sentinel_2023_q1.tif")
after  = arcpy.Raster("sentinel_2024_q1.tif")

# Band math: NDVI = (NIR - RED) / (NIR + RED)
ndvi_b = (before.getBand(4) - before.getBand(3)) / \
         (before.getBand(4) + before.getBand(3))
ndvi_a = (after.getBand(4)  - after.getBand(3))  / \
         (after.getBand(4)  + after.getBand(3))

delta = ndvi_a - ndvi_b

# Extract deforestation polygons (NDVI loss > threshold)
loss_mask = arcpy.sa.Con(delta < -0.15, 1)
arcpy.conversion.RasterToPolygon(
    loss_mask, "deforestation_output.shp",
    simplify=True
)
arcpy.AddMessage("Change detection complete")
